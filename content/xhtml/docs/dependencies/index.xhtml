Dependencies

The libraries your project uses, and the libraries those use in turn.

How-to guides

  • Find out where a dependency comes fromSee which of your dependencies brings in a library, which version won and why, and which libraries you use without declaring them.
  • Control the version of a transitive dependencyChoose the version of a library that your dependencies bring in, for example to pick up a security fix, and make the build fail when a dependency needs a newer version than it gets.
  • Exclude a transitive dependencyKeep a library that one of your dependencies brings in off your classpath, and make sure it does not come back through another path.
  • Use a BOM, and publish oneImport a bill of materials to get matching versions of a library family, override one of its versions, and publish a BOM for your own library.
  • Make a dependency optionalLet your library use a dependency for one feature without passing it on to every project that uses the library.

Repositories

The servers Maven downloads libraries from and deploys your own artifacts to.

How-to guides

  • Use a repository manager as a mirrorSend every download through your organisation's repository manager instead of Maven Central and the repositories projects declare.
  • Use several repositoriesDeclare extra repositories in a POM or in a settings.xml profile, and the order in which Maven asks them.
  • Install a third-party JAR locallyPut a JAR that is in no public repository into your local repository with install:install-file.
  • Deploy a third-party JAR to a remote repositoryDeploy a JAR that is in no public repository to your organisation's repository with deploy:deploy-file, with a generic POM or your own.
  • Use an HTTPS repository that asks for a client certificateStore the client certificate and the certificate of the server, and point Maven at both with javax.net.ssl system properties.
  • Run one repository manager for hundreds of projectsRoute the downloads and uploads of hundreds of projects through one repository manager, with settings.xml files that you manage centrally.
