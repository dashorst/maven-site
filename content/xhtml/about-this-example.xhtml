About this example

This is a proposal for maven.apache.org, not the official site. I made it, unasked, to show what the Maven documentation could look like with a different structure and one writing standard.

While redesigning the website of Apache Wicket, I saw the documentation effort on dev@maven and figured I could try for Maven what I did for Wicket: turn the existing documentation into tutorials, how-to guides, reference and explanation, following Diátaxis, and then find a structure for the whole site. Everything here is built from the sources of apache/maven-site.

Martijn Dashorst

What I changed

  • The structure. Five tabs, Docs, Downloads, News, Extend and Community, instead of one long menu, so users, plugin authors and contributors each have their own way in. Every page sits in a group of related pages, with previous and next.
  • A guide that follows one standard. 24 pages, each with one job: a tutorial, a how-to guide, a reference or an explanation. Every command on them was run on Maven 3.9.16, 3.10.0 and 4.0.0-rc-7. They replace the Maven pages they were written from.
  • A frame of its own. Maven navy and the feather’s orange, the Maven wordmark, and on every page the versions it holds for, when it changed, and where to edit it or report a problem.
  • No JavaScript needed. Every page, menu and list works without it. JavaScript only makes the search answer as you type, and adds the “On this page” list and links on headings; without it, search opens a page listing every page.
  • Old addresses stay. Maven’s own pages keep the address they have on maven.apache.org; only the guide pages and the overview pages are new.

What I left as it is

The other 150 or so pages are Maven’s own, carried over unchanged into the new structure: from pages written for Maven 2 to pages written for the Maven 4 betas, in as many voices. They say “Not yet checked against Maven 3.9, 3.10 and 4.0”, because they aren’t. They would need the same treatment as the guide pages. I changed Maven’s text in one place only, a published TODO; CONTENT-FIXES.md lists it.

What the standard looks like

Each kind of page does one job:

  • Tutorial: a lesson that builds something that works, step by step.
  • How-to guide: directions to reach one goal, for someone who already knows the basics.
  • Reference: the facts, complete and in a fixed order: elements, options, files.
  • Explanation: why Maven works the way it does.

The rules the guide pages follow, from front matter to how Maven 4 differences are marked, are in GUIDE.md. They could extend Maven’s own documentation style guide, which so far covers dates and POM indentation.

What turned up along the way

Running every command on three Maven versions turned up 48 places where Maven’s documentation and Maven’s behaviour disagree: outdated advice, examples that no longer work, and Maven 4 changes the pages don’t mention. They are on their own page, as a list to check.

How I made it

I built this with an AI assistant, Anthropic’s Claude, using the impeccable design skill for the structure and the front page. The guide pages were written from Maven’s own pages, and every command on them was run on the three Maven versions before it went in. Before building, the current site was reviewed against usability heuristics, the new navigation was tree-tested with 18 tasks, and the home page was put to a panel of reader personas; the testers and the personas were simulated by the AI, not real users.

This version of the example is built with Maven’s own tooling: mvn site, maven-site-plugin and Doxia, from the same sources as maven.apache.org. The frame is a skin of its own (doxia/skin), the structure is the site descriptor content/site.xml, one menu three levels deep, and the landing pages, the news and the A–Z index are Markdown pages written from the same data by a small script. After the pages are rendered, two small classes run from the POM colour the code (Highlight) and write the search index (SearchIndex). Not in this version: the date a page last changed; moving pages to new addresses would add .htaccess redirects. The version built with Jekyll has those.

What is still missing

  • The plugin sites and the reference documentation are not part of this build, so links to them still lead to the current design.
  • The pages I left as they are have not been checked against the three Maven versions.
  • There is no single page yet on where Maven 4 stands and how to migrate.
