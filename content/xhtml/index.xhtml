What Maven does

Dependency management, made boring

Declare each library by its coordinates, group, name and exact version, and Maven fetches it and what it depends on from Maven Central.

  • One version of each library, fixed in one place for all your modules.
  • A new release reaches your build only when you change a version.
  • Downloads over HTTPS by default since Maven 3.8.1, and downloading a library runs none of its code.

Automate upgrades with the Versions Maven Plugin from MojoHaus, and review the diff.

How dependencies work

<dependency>
  <groupId>org.apache.commons</groupId>
  <artifactId>commons-lang3</artifactId>
  <version>3.17.0</version>
</dependency>

$ mvn versions:display-dependency-updates
[INFO]   org.apache.commons:commons-lang3 ... 3.17.0 -> 3.21.0
$ mvn versions:use-latest-releases   # updates the POM; review the diff

Builds, made exceptionally boring

Yes, it’s XML, and yes, you write versions down instead of letting them float. Here is what you get for it: build the same sources twice and you get the same JAR, byte for byte. Since Maven 3.10 reproducible builds are on by default.

Reproducible builds

$ mvn clean package && sha256sum target/my-app-1.0.jar
0b9b589c9d53…  target/my-app-1.0.jar
$ mvn clean package && sha256sum target/my-app-1.0.jar
0b9b589c9d53…  target/my-app-1.0.jar

Compile, test, package, repeat

Every Maven project builds through the same main phases, in the same order, on your laptop and in CI. Learn them once, and you can build any Maven project you clone. With the Maven Wrapper the build also runs on the same Maven: ./mvnw verify.

Phases, goals and plugins

validate → compile → test → package
         → verify → install → deploy

$ mvn verify   # validate … verify, in order

There’s a plugin for that

Compiling, testing and packaging are plugins, and so are many other jobs: a runnable JAR, a project site, signed artifacts for a release. Many you run straight from the command line; others you add to the POM and configure like any other.

Big builds, one command

Split an application into modules and one mvn verify from the root of your project builds them all, each after the modules it depends on. Working on one? -pl picks a module by its directory, -am adds the modules it depends on, and -T builds independent modules in parallel.

Build part of a project

$ mvn verify             # every module, in order
$ mvn -pl app -am verify # app and what it needs
$ mvn -T 1C verify       # independent modules in parallel

Faster builds with mvnd

The Maven Daemon keeps Maven running between builds, so the next build starts warm. Install it next to Maven, then type mvnd instead of mvn: same projects, same goals.

Maven Daemon

$ mvnd verify

Maven 4 is almost here

Maven 4.0.0-rc-7 is expected to be the last release candidate before Maven 4.0.0. Try it on your build now and report what breaks.

  • Maven 4 needs Java 17 to run, and still compiles for older Java.
  • Subprojects no longer repeat their parent’s coordinates.
  • Phases get before- and after-phases to hook into.
  • The Maven Upgrade Tool checks your POMs and updates them.
