How-to guides

Directions for a specific goal.

Configure Maven

  • Use a repository manager as a mirror Send every download through your organisation's repository manager instead of Maven Central and the repositories projects declare.
  • Connect through an HTTP proxy Make Maven download through the HTTP proxy your network requires, with a login if the proxy asks for one and exceptions for internal hosts.
  • Store credentials for a repository Give Maven the username and password for a repository it downloads from or deploys to, matched to the repository by id.
  • Encrypt passwords in settings.xml Replace the plain passwords of servers and proxies in settings.xml with encrypted values, with a master password on Maven 3 or mvnenc on Maven 4.

Multi-module projects

  • Split a project into modules Turn one Maven project into a parent POM with modules that depend on each other and build together from the root directory.
  • Build part of a multi-module project Build one module, a module with the modules it needs or with the modules that use it, leave modules out, or resume a failed build.
  • Share dependency versions and plugin configuration Set dependency versions, plugin versions and plugin configuration once in the parent POM, and import a BOM, so that every module uses the same.

JDKs and toolchains

  • Build with a different JDK than Maven runs on Compile, test and package a project with a JDK of your choice while Maven itself keeps running on the JDK in JAVA_HOME.
  • Compile for an older Java version Build classes that run on an older Java than the JDK you build with, check them against that Java's API, and run the tests on it.
